# 执行说明和数据格式

已有项目补充资料、保留人工修改、同名修订件和中断恢复，先读[incremental.md](incremental.md)。首次整理按本文件执行，完成后登记项目状态。

## 运行环境

使用当前Codex提供的Python、Node及`@oai/artifact-tool`，不要固定任何电脑的盘符、用户名、运行时版本。Python依赖见`scripts/requirements.txt`；缺少时安装到本任务独立环境，不修改全局或内置运行时。OCR模型由RapidOCR包自带，CPU可运行，有兼容GPU时可加速。宋体优先取当前电脑字体，缺少时封面使用PyMuPDF内置中文字体并检查是否满足用户版式要求。

Node在任务独立目录建立`node_modules`链接到当前运行时包目录；把本技能的`build_workbook.mjs`复制到该目录运行，才能解析`@oai/artifact-tool`，不改内置依赖。原始xlsx示例读取要限制最大列数（案卷18、卷内13），不要依赖全表使用范围。

## 目录约定

```text
项目工作目录/
  输入资料/               用户PDF、图片或ZIP，保留原件
  最终成果/               一个六表.xlsx + 档号命名PDF，直接同层
  过程资料归档/           清点、OCR、JSON、依据、差异清单、预览
```

脚本参数显式传入上述路径，不得把本技能安装目录作为项目数据目录。大批量处理缓存以源哈希+PDF页码绑定，断点续作不重复叠加页码；输出文件存在时默认停止，先备份或选空目录。

## 识别与判定

1. `prepare.py inventory 输入资料 --work 过程资料归档`：校验PDF、ZIP CRC、记录文件来源和哈希；密码、损坏、截断材料单独列出，不能按部分恢复件声称整包齐全。图片先转PDF，原图保留。
2. `prepare.py ocr 过程资料归档/input_inventory.json --work 过程资料归档 --mode structure`：读封面、目录续页、首个正文及最后三页。需要责任者、缺失页号等证据时用`--pages 3,12,80`指定页，或`--mode all`读取全卷。支持横向、竖向扫描时要看原图校正OCR结果，不能把转向失败当空白。
3. 建立源文件→卷段→目录条目→PDF页的映射。一个PDF含多卷时，以封面/备考表分段；每段用`source_pages`列出源PDF页码。同一页有两张照片可对应两个条目，不必拆PDF；照片目录按全册实际条目全部抄录。
4. 责任者依据优先级：正文落款/印章/发证机关或检测单位栏 → 直接对应原卷内目录责任者栏 → 可验证的同项目同系列表式。只有封面立卷单位不足以判断全部卷内文件；不得把报告的委托单位误作检测出具单位。混合卷分别填写文件责任者，再汇总至案卷级。
5. 保存“责任者判断依据”和“保管期限条目依据”在过程资料，通常用一个CSV即可。责任者证据标注卷号、PDF实际页码、字段原文；若按相同表式推广，要记录样本及适用范围。
6. 文件页号读原目录并与正文核对。原扫描缺页或原编号跳号时，电子连续页码照实际页数生成；目录可保留原档案页号并注明与电子索引的关系。禁止把某文件的起页误当总页数，也不要根据目录最大数字推断卷页数。

## 已核对清单数据

`reviewed_manifest.json`示例：所有页码为源PDF中从1开始的实际页序。以下内容只是数据格式示例，不属于新工程的事实。

```json
{
  "project": {
    "name": "本次工程全称",
    "short_name": "本次工程简称",
    "archive_code": "SIGJ-JS01-XXXX",
    "company": "九建公司",
    "type": "公路",
    "compiler": "扫描件确认的立卷单位",
    "date": "2026-11-12"
  },
  "volumes": [{
    "volume_no": 1,
    "source": "../输入资料/第一卷.pdf",
    "source_cover_page": 1,
    "title": "材料试验检测报告",
    "period": "20240101-20241231",
    "kind": "文件",
    "body_pages": [3,4,5],
    "excluded_pages": [2,6],
    "files": [{
      "title": "材料试验检测报告",
      "number": "报告编号",
      "date": "20240101",
      "page_ref": "1-3",
      "creator": "实际检测机构全称",
      "creator_evidence": [{"page":3,"kind":"issuer_heading","unit":"实际检测机构全称","quote":"试验检测单位名称：实际检测机构全称","confidence":"high"}],
      "page_ref_system": "electronic",
      "source_pdf_pages": [3,4,5],
      "retention": "永久",
      "retention_basis": "管理办法6.1.5",
      "notes": "页号为本次电子正文索引，原报告页码保留"
    }]
  }]
}
```

`source_cover_page:null`代表无案卷封面，构建时新增一页，不能删除源第一页。`source_pages`省略代表全PDF；拆卷时填升序去重的源页码列表，`source_cover_page`必须是该段第一张页。`body_pages`、`excluded_pages`、封面需覆盖所选每一页并互不重叠。`excluded_pages`仅用于案卷目录、备考表或经确认的无效空白页，不能任意排除有内容页面。

文件责任者、责任者依据、页号、保管期限、期限条目为必填。电子生成不负责猜测这些字段。无法识别时明确填“责任者待核对”或“页号待核对”，在依据或备注中写出原因，输出核对稿。整卷保管期限由文件期限自动取最高；卷内级公司字段取project.company，默认九建公司。

`period`和文件`date`分别为整卷起止日期、文件形成日期，不能互相批量替代。不要把默认系统日期填入历史档案形成日期。无来源的开竣工日期、合同金额等留待确认。

## 生成

以下Python、Node替换为当前运行时实际可执行文件。路径含空格或中文时作为独立参数正确引用。

```text
python scripts/archive_runtime.py build reviewed_manifest.json --output 最终成果 --work 过程资料归档
node build_workbook.mjs 过程资料归档/workbook_payload.json 最终成果/项目三级目录（整理核对稿）.xlsx 过程资料归档/目录预览
python scripts/print_settings.py 最终成果/项目三级目录（整理核对稿）.xlsx
python scripts/archive_runtime.py audit reviewed_manifest.json --workbook 最终成果/项目三级目录（整理核对稿）.xlsx --output 最终成果
```

仅更新责任者等目录字段时使用`build --metadata-only`，避免再次生成、加印PDF页码。已有PDF无需因补目录字段重做。可使用模板原有六表，不能增加一个“汇总”工作表代替缺失的移交表。

制作过程中默认保存检查点，同一工作目录重跑会核验并跳过已完成卷。半成品从原始扫描件重建，不从已加过页码的成品继续叠加。仅因元数据改变需要重建已有PDF时，使用`--refresh`保留备份；被外部改动的PDF不自动覆盖。

## 验收

- 目录六表齐全；案卷数等于PDF数；所有档号、源文件哈希绑定一致；移交目录和案卷级题名、页数、期限一致；预归档登记表永久/30年统计一致。
- 案卷题名含本项目全称；无示例项目0083、若羌等历史内容误带入。立卷单位与责任者分别核对，卷内每条有责任者，公司名称为九建公司或用户新指定值。
- 所有新封面文字完整、不压线、不越框；选首卷、最长题名、不同期限卷、照片卷、图册查看。每卷检查正文首末页及页码，封面、目录、备考页不编号；原有图号和手写号不擦除。
- 源文件哈希不变，输出正文图像保持一致；PDF页数只在新增封面或明确拆卷时改变。损坏包、缺页、原目录自身页号错误、日期识别不清等列过程核对清单，不隐瞒也不编造。
- 渲染六表中受影响范围检查，文本换行不裁切；必要时补Excel打印重复标题和横向适配，保持参考样式。

发现OCR误拆长题名、目录漏页或页号错位，回到相应源页更正清单后重建数据；不能靠改变总数让检查通过。此技能的模板和参考不等于对新扫描件的事实背书。
